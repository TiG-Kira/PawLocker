# 两端交互细节

本文说明用户实际看到什么、点什么、界面之间怎么跳转。
代码位置对照表在文末。

---

## 1. 总览：一次解锁要经过几双手

```
① 用户在手机上点【解锁】
        │
        ▼
② 手机唤起本机生物验证（指纹 / 面容 / 设备 PIN）
        │  验证不通过 → 流程到此为止，一个字节都不发出去
        ▼
③ 手机用身份私钥签名 + AES-GCM 加密解锁指令
        │
        ▼
④ 经局域网 / frp / 虚拟组网送到电脑的 28900 端口
        │
        ▼
⑤ 电脑验签 → 查防重放（时间戳 / 计数器 / nonce）→ 解密
        │  任一项不过 → 回一条错误码，不执行任何动作
        ▼
⑥ 按已配置的策略执行：唤醒屏幕 / 提交凭据 / 跑自定义命令 / 只记日志
        │
        ▼
⑦ 回执（同样带签名）→ 手机显示结果
```

每一步失败都有对应用户可见的文案，见 §5。

## 2. Android 端

### 2.1 导航结构

刻意不用 Navigation 库：全应用只有 4 个目的地，
而「配对结束自动回设备页」这种逻辑用状态机表达比路由栈更直白。

```
              ┌──────────────────────────────┐
              │  默认落地：设备页             │
              │  （已匹配的电脑列表）         │
              └───┬──────────┬───────────┬───┘
                  │          │           │
        点【匹配新电脑】  点某台电脑   点某台电脑
                  │      的【详情】    的【解锁】
                  ▼          ▼           ▼
             配对页      设备详情页   （就地执行）
                  │
        配对成功/失败/超时
                  │
                  └──────▶ 自动回设备页（在设备页展示 SAS 比对或失败原因）
```

- 系统返回键只在非设备页时生效，一律回设备页（`BackHandler`）
- 详情页按 `deviceId` 重新取记录 —— 记录可能刚被删除，取不到就自动退回

### 2.2 设备页（默认页）

每台电脑一张卡片，卡片上：

| 元素 | 说明 |
|---|---|
| 电脑名 | 配对时电脑端上报的显示名 |
| 状态胶囊 | 依据「上次连通性探测结果 + 最近使用时间」给出可达 / 不可达 / 未探测 |
| 【解锁】 | 主操作，详见 §2.3 |
| 【详情】 | 进详情页：设备信息 / 可达地址 / 连通性测试 |
| 【删除】 | 二次确认后从信任列表移除 |

页面顶部有一个「＋」用于进配对页。列表为空时是引导态，直接指向【匹配新电脑】。

### 2.3 点【解锁】之后

这是一个**有阶段感的**过程，界面上会依次显示：

```
「正在验证身份…」  ← 生物识别弹窗（系统绘制，不是我们的 UI）
        │
        ▼ 验证通过
「正在连接电脑…」  ← 按 Endpoint.preferredOrder 逐条尝试
        │           局域网 → 虚拟组网 → 隧道
        ▼
「正在发送解锁指令…」
        │
        ▼
   结果提示
```

**生物识别不过就不发包。** 这是硬约束：`DeviceSideController.unlock()` 里
先 `await` 闸门，拿到不通过的结果直接返回并提示，网络层的代码根本不会被执行。

同一时刻只允许一个解锁在途（`unlockingDeviceId` / `unlockingStage` 是单例状态），
避免连点产生多条指令。

### 2.4 配对页

两条路径，用顶部切换器二选一。

#### 路径一：扫码

1. 电脑端在管理页点【生成配对码】→ 显示二维码 + 6 位配对码
2. 手机切到「扫一扫」，对准二维码
3. 自动解析出深链 `pawlocker://pair?d=...`，连接、交换公钥、完成配对

二维码里装的是 `PairingOffer`：地址列表 + 配对 ID + **电脑公钥指纹** + 一次性 nonce。
**6 位配对码不在二维码里** —— 它是唯一带外信息，这正是防中间人的关键（见 `docs/02-crypto-and-pairing.md` §3）。

#### 路径二：手动输入

适合摄像头不可用、或二维码已经过期的情况。四个字段：

| 字段 | 说明 |
|---|---|
| 主机地址 | 电脑的 IP / 域名 / frp 服务器地址 |
| 端口 | 默认 28900 |
| 配对码 | 电脑端显示的 6 位数字，**必须在电脑屏幕上读** |
| 连接方式 | 局域网 / 虚拟组网 / 隧道 / 自定义，仅影响显示与优先级 |

配对码位数不对时输入框边框标红，不发请求。

手动路径与扫码路径的**安全性等价**：
`ServerHello` 会带上当前配对窗口的 `activePairingId` 与电脑公钥，
手机用它和配对码一起算 `confirmTag`，中间人依然要同时伪造公钥和配对码才能通过。

配对过程中：
- 页面显示 `PairingBusyOverlay`，挡住重复操作
- 电脑端会弹「有手机请求配对，是否允许？」，**必须有人在电脑上点允许**
- 最长等待 60 秒，超时给明确文案

配对成功后：
1. 自动回设备页，新电脑出现在列表里
2. 弹出 **SAS 比对** 对话框 —— 两端显示同一组 emoji（4 个）
3. 用户肉眼比对两边一致 → 点「一致」；不一致 → 点「不一致」并立即删除这条记录

> SAS 不是必需的（配对码已经防住了中间人），而是**第二道肉眼可验证的保险**。
> 它的价值在于：即使配对码在传递过程中被偷看，两端的 emoji 也会在中间人存在时对不上。

### 2.5 设备详情页

三组卡片：

| 卡片 | 内容 |
|---|---|
| 设备信息 | 显示名、型号、平台、设备 ID、配对时间、最后活跃时间 |
| 可达地址 | 该设备记录的全部 Endpoint（类型 + 主机 + 端口 + 优先级） |
| 连通性 | 【测试连接】按钮 → 逐条尝试，显示每条的成功/失败与耗时 |

### 2.6 设置页

| 卡片 | 内容 |
|---|---|
| 本机身份 | 设备名、系统、应用版本、设备指纹 |
| 安全 | 已匹配电脑数量、协议版本 |
| 数据位置 | 应用数据目录、配对记录文件名 |
| 危险操作 | 【重置本机身份】—— 二次确认后删除身份密钥与全部配对记录 |

## 3. Windows 端

### 3.1 同一个 exe，两种形态

由命令行参数决定：

| 参数 | 形态 | 窗口尺寸 | 用途 |
|---|---|---|---|
| （无） | 管理主窗口 | 1080×760，可缩放 | 日常使用 |
| `--login-window` / `-l` | 登录小窗 | 420×620，固定，**置顶** | 从锁屏/托盘单独唤起 |

做成一个二进制而不是两个程序：两者共享同一份配置、同一个数据目录、
同一套身份密钥。拆成两个 exe 会在「谁持有 28900 端口」上立刻打架。

### 3.2 首次启动：注册向导

**这是 Windows 端第一次运行时强制走的一步。**
PawLocker 不是一个纯应用内功能 —— 它要在系统层面挂钩子，
所以必须让用户明确知道「接下来会改动系统的哪些地方」。

三步：

```
① 开始之前            ② 选择解锁方式         ③ 向 Windows 注册
   会改动什么            决定收到指令后          逐项执行，每项单独弹 UAC
   全部列出来            电脑做什么               任何一项都可以跳过
```

#### 第 ① 步：开始之前

明确列出三项系统改动，不做任何隐藏：

| 改动 | 是否需要管理员 |
|---|---|
| 放行监听端口 | 是（防火墙规则） |
| 安装登录组件（可选） | 是（HKLM 注册表） |
| 开机自动运行（可选） | 否（HKCU 启动项） |

底部有【先跳过，我自己在设置页里配】—— 跳过不会导致程序不可用，
只是功能不全，之后随时能在设置页补。

#### 第 ② 步：选择解锁方式

四条策略，选择「凭据提供程序」时会额外解释它的能力与前提：

| 策略 | 能做到什么 |
|---|---|
| **凭据提供程序** | 真正完成登录。需要 `PawLockerProvider.dll` |
| **仅唤醒屏幕** | 只点亮显示器，不解锁。零依赖 |
| **自定义命令** | 执行你指定的任意命令 |
| **仅记录日志** | 不产生任何系统影响，用于先跑通链路 |

#### 第 ③ 步：向 Windows 注册

- 顶部先显示**要做什么的清单**（还没做的项）
- 每一项一个按钮，点一下弹一次 UAC
- 每项下面写清楚「不加这条会怎样」，而不是只写「点击添加」

各项的具体动作：

| 项 | 实现手段 | 判断「已经做过」的依据 |
|---|---|---|
| 放行端口 | `netsh advfirewall firewall add rule` | 按规则名 `PawLocker (TCP <端口>)` 反查 |
| 注册凭据提供程序 | 生成 UTF-16LE 的 `.reg` 交给 `reg import` | HKLM 下 CLSID 与 Credential Providers 两个键都在，且 DLL 文件确实存在 |
| 开机自动运行 | 写 `HKCU\...\Run` 的 `PawLocker` 值 | 该值存在且路径与当前 exe 一致 |

**提权方式**：统一走 `powershell Start-Process -Verb RunAs -Wait`，
由系统弹 UAC，而不是要求「右键以管理员身份运行整个应用」。
好处是**只有该操作提权**，主程序始终以普通用户权限运行。

用户取消 UAC 会被识别出来，显示「已取消」而不是「失败」——
这两件事对用户的含义完全不同。

注册全部完成后点【完成】，进入管理页。

### 3.3 管理页

左侧固定导航，四页：

| 页面 | 内容 |
|---|---|
| **信任手机** | 已匹配的手机列表，可逐个【删除】；显示设备名、型号、最后活跃时间、SAS |
| **配对** | 【生成配对码】→ 二维码 + 6 位码 + 剩余有效期；有手机请求时弹【允许/拒绝】 |
| **活动** | 事件日志（上限 200 条）：解锁成功/失败、配对请求、连接被拒、限流触发 |
| **设置** | 端口、穿透、解锁策略、注册状态体检 |

#### 信任手机页

每台手机一张卡片，删除需要二次确认。
删除是**立即生效**的：该手机的 deviceId 从服务端信任列表移除后，
后续请求会在 `handleUnlockRequest` 的第一步就被拒绝。

#### 配对页

- 点【生成配对码】打开配对窗口（默认有效期 120 秒）
- 页面上显示二维码（手机扫）与 6 位数字（手机手动输入时用）
- 手机连上后弹出审批对话框，显示请求方的设备名、型号、deviceId
- **必须有人点【允许】**，否则手机那边会在 60 秒后超时
- 配对窗口可以随时手动关闭，关闭后新请求立即被拒

#### 设置页

| 卡片 | 内容 |
|---|---|
| 监听 | 端口、绑定地址 |
| 穿透 | 启用开关、frp 服务器地址与端口、令牌、远程端口、`frpc.exe` 路径、子进程状态 |
| 虚拟组网 | 提供方（Tailscale / ZeroTier）、本机虚拟 IP |
| 解锁方式 | 四选一 + 自定义命令输入 |
| Windows 注册 | 逐项的当前状态，可单独补做或撤销；【重新运行向导】 |
| 凭据 | 设置 Windows 登录用户名与密码（只进不出，读回来只显示「已配置」） |
| 关于 | 版本、数据目录、密码学后端 |

> 「凭据只进不出」是刻意的：密码回显会成为肩窥与截屏泄露的入口。
> 用户要改就重设，不提供查看。

### 3.4 登录窗口

从锁屏/托盘以 `--login-window` 唤起。它的定位是
**「人已经在电脑前，但屏幕锁着，手机在身上」**。

界面状态机：

```
「正在等待手机指令…」        ← 主状态
        │
        │ 收到并校验通过的解锁指令
        ▼
「解锁成功」
        │
        │ 失败 / 超时
        ▼
「失败：<人话原因>」→【重试】
```

窗口置顶、不可缩放 —— 它被别的窗口盖住就失去了存在意义。

**注意**：这个窗口本身不完成登录。它只是「被唤起并展示状态」的那一扇窗；
真正让用户进桌面的是 Credential Provider（见 `credential-provider/README.md`）。

## 4. 状态在两端各自表现成什么

| 情况 | 手机端 | 电脑端 |
|---|---|---|
| 服务未启动 | 连接失败，提示「电脑端服务好像没开」 | 管理页顶部显示服务已停止，【启动】按钮可用 |
| 端口被占用 | — | 启动时报错并指出是哪个端口、让用户改端口 |
| 配对窗口未打开 | 连接被拒，提示「电脑上还没打开配对窗口」 | 配对页显示【生成配对码】 |
| 配对等待审批 | 配对转圈，最长 60 秒 | 弹出审批对话框 |
| 手机不在信任列表 | 收到 `NOT_TRUSTED`，提示需重新配对 | 活动页记录一条「未知设备尝试解锁」 |
| 指令过期（时钟偏差） | 收到 `EXPIRED`，提示检查两端时间 | 活动页记录 |
| 计数器回退（重放） | 收到 `REPLAY_DETECTED` | 活动页记录一条**安全告警** |
| 频繁失败 | 触发退避，提示「操作太频繁，请稍后再试」 | 限流命中记入活动页 |

## 5. 错误码到人话的映射

`DeviceSideController.friendlyReason()` 负责这层翻译。
原则是：**告诉用户下一步能做什么**，而不是把错误码丢给他。

| 错误码 | 手机端文案 |
|---|---|
| `NOT_TRUSTED` | 这台电脑不认识本机，请在电脑上重新配对 |
| `EXPIRED` | 指令已过期，请检查两台设备的时间是否一致 |
| `REPLAY_DETECTED` | 这条指令之前已经用过了 |
| `BAD_SIGNATURE` | 指令签名校验失败，可能不是本机发出的 |
| `PAIRING_CLOSED` | 电脑上没有打开配对窗口 |
| `PAIRING_TIMEOUT` | 电脑端没有及时确认，请重试 |
| `PAIRING_CODE_MISMATCH` | 配对码不对，请核对电脑屏幕上显示的数字 |
| `RATE_LIMITED` | 尝试太频繁，请稍后再试 |
| `UNSUPPORTED_VERSION` | 两端版本不匹配，请把应用都更新到最新版 |
| `INTERNAL_ERROR` | 电脑端出错了，详情请查看电脑上的活动日志 |
